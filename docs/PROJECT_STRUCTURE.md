## Content Structure

### Multi-language Pages

French pages at root level, English in `en/`:

```text
index.md          → /
en/index.md       → /en/
resume.md         → /resume/
en/resume.md      → /en/resume/
```

### LinkedIn carousels

Each carousel in `linkedin/carousels/` is a standalone HTML page built from `template.html`, with 1080×1080 slides.
Export it with `linkedin/carousels/export-pdf.sh linkedin/carousels/<carousel>.html`: the script captures each slide
as a PNG with headless Chrome and builds the PDF from those images. The browser's own print to PDF draws a hairline
frame around the gradient text. The folder is excluded from the sitemap.

### CV PDF

`_layouts/cv-print.html` builds an A4 CV from the Notion data (rows with the Print box, see
[`NOTION_SETUP.md`](NOTION_SETUP.md)), in two variants: `visual` (dark sidebar, site colors) and `ats` (one column,
standard headings, period and contract on one line). The pages are `cv-print.html`, `cv-print-ats.html` and their
`en/` copies (`/cv/print/`, `/cv/print/ats/`, `/en/cv/print/`, `/en/cv/print/ats/`), out of the sitemap and noindex.
Page texts live in `cv_print` in `_data/translations.yml`, styles in `_sass/pages/_cv-print.scss`
(`assets/css/cv-print.scss`). The PDFs use the static Inter files in `assets/fonts/inter/`: Chrome embeds them as
TrueType, which ATS parsers read, whereas a variable or system font becomes Type 3.

`scripts/export-cv.sh` serves a built site and prints the four pages with headless Chrome to `assets/cv/`
(`make cv`) or `_site/assets/cv/` (deploy workflow). The resume pages link to them through
`_includes/components/cv-download.html`.

### Collections

Jekyll collections in `_collections/` serve as fallback data when Notion is not available:

```text
_collections/
├── _experiences/     → site.data.notion_experiences (fallback)
├── _skills/          → site.data.notion_skills (fallback)
├── _testimonials/    → site.data.notion_testimonials (fallback)
├── _posts/           → blog posts, written in Markdown
└── ...
```

Blog posts live in `_collections/_posts/`, one file per language, named `YYYY-MM-DD-<slug>-<lang>.md`. Each sets
`lang`, a `permalink` (`/blog/<slug>/` in French, `/en/blog/<slug>/` in English) and `alternate_lang` /
`alternate_url` for hreflang. Their images go in `assets/images/posts/<slug>/`. `_config.yml` lists `_collections`
under `include`: Jekyll skips underscore folders when it looks for posts, so without it no post is built.

Posts use `_layouts/post.html` (styles in `_sass/pages/_post.scss`): a hero panel like the experience pages (back
link, tags, title, description, date, reading time), then the cover and the Markdown body in a 768px column. Write
image URLs as `{{ '/assets/images/posts/<slug>/<file>' | absolute_url }}`: the page shows them in development, and
the production build gives the absolute URLs that Medium and dev.to need. An italic line right after an image is
styled as its caption.

`blog.html` (`/blog/`) and `en/blog.html` (`/en/blog/`) list the posts of their language, newest first, through
`_includes/sections/blog-list.html` (styles in `_sass/pages/_blog.scss`). The header, the mobile menu and the footer
link to the blog index of the page language.
